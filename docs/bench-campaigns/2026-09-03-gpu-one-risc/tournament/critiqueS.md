# CRITIQUE — synthAB, round 2

## 1. Risk surface

**RS-1 (card 1.1).** The census the card mandates is a global mutex on the per-dispatch path. It says mirror `WIDTH_TILE_DECLINE` "verbatim" — that is `static WIDTH_TILE_DECLINE: Mutex<BTreeMap<(u32, WidthDeclineReason), WidthDeclineTotals>>` at `proxima-tensor/src/instrument.rs:842`, with `record_width_tile_decline` doing `.lock()` then `.entry().or_insert()` at `:848-864`. Its neighbour is `counter!(ENCODE_DISPATCH_CALLS, 1)` at `omega/src/metal.rs:2243`, a `proxima_telemetry::Counter` declared at `metal.rs:1484` — an atomic add. The card equates two different cost classes and never says so.

**RS-2 (card 5.5).** The relaxed predicate is unsound as written. Both validators compare element counts: `omega/src/metal.rs:991-1000` (`let expected = element_count(shapes.of(*node)); let found = block_element_count(block)?; if found != expected`) and `proxima-tensor/src/cpu.rs:346-356` (`if data.len() != expected`). 5.5 writes `if found != expected && Some(found as u64) != declared_capacity[i]`. `declared_capacity` is supplied by the same caller that supplies the block, so `declared == found` is free, and the guard degenerates to "accept any length, including a truncated one." Its own test (c) ("an under-allocated block is still rejected on both") cannot hold alongside test (a) under that predicate. The relation the card needs is `declared >= expected`; it never states it.

**RS-3 (card 4.2).** The card names use-after-retire as its hazard but its four tests do not cover retirement order. The owner of that order is `bound_op_retirement`, called at `omega/src/metal.rs:1013` and consumed by `execute_plan` (`:449-568`); neither appears in the card's `opens`. Test (b) ("live buffer count is bounded in steady state") does not exercise a pooled output that is still an operand of a later op.

## Summary — the three most consequential findings

The plan's own spine defeats itself in three places. First, **card 1.1 instruments the exact slice card 4.3 measures**: it mandates a `Mutex<BTreeMap>` census (`instrument.rs:842`, `:848-864`) at `metal.rs:2244`, beside an atomic `counter!` (`metal.rs:2243`), fired 1196 times per token inside `encode_op` — and bounds it only with `gpu_exec_ms < 0.7%`, a device-window counter (`metal.rs:547-554`) that cannot see a CPU lock, while every measuring command hardcodes `--features …,instrument`; so every Phase-4 delta against R13's `op_setup` 3.9 / `prepare` 1.97 / `encode_dispatch` 0.47 is taken on a tree carrying an unmeasured serialization R13's tree did not have, and no OFF arm exists anywhere in 44 cards. Second, **card 0.10's "one bound plan" test is vacuous where it is taken and already refuted where it matters**: `bind` (`bind.rs:1718-1722`) has no backend parameter, so fingerprinting its return across four consumers compares one pure function to itself, while the actual second rewrite engine — `correct_packed_matmul_layouts(&mut resolved, …)` at `metal.rs:1012`, which repairs every packed Q4_K/Q5_K/Q6_K stride on the Metal path and only there — is absent from the card's `opens`, so brief item 1 is asserted by a test that cannot fail against a fact the plan never read.
