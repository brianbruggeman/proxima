The same arithmetic breaks 5.2's cap: prefill 4.305e9 + the 512-token arena 134,217,728 = 4.439e9 > 4,316,577,792.

**B8 — 6.1's `op_count` kill fires on the best outcome.** Quoted: N4 *"`op_count` rises by **exactly 2**"*, kill *"`op_count` delta ∉ {2, 34} ⇒ the graph changed in a way this card did not design."* The card's own four nodes are `kv_valid_len` (`Op::Input`), `cache_slot` (`Op::Iota`), `is_valid` (`Elementwise{Greater}`) and 32× `score_masked` (`Elementwise{Select}`). `BoundOpKind` has no `Input` variant (`bind.rs:221-264`, four variants), so the leaf is never a bound op; if the `Greater` fuses into the `Select`'s `ComposedBody` and the `Select` into the existing score body — the card's own stated expectation for the `Select` — the delta is **+1** (the `Iota` alone), which is outside `{2, 34}` and kills a card that behaved better than designed.

**B9 — 6.1's `+3 → +4` literal is wrong in both directions and unverifiable.** Quoted: *"the `+ 3` capacity literal at `:1316` becomes `+ 4` — exactly one, because the leaf is layer-invariant."* On main `generate.rs:1313-1318` reserves `… + 3 + layer_caches.len() * 3` while the code pushes **four** fixed blocks: `:1322` `"ids"`, `:1332` `"eps"`, `:1333` `"rope_cos"`, `:1334` `"rope_sin"`. So `+3` already under-counts by one, and `+4` still under-counts by one after a fifth block is added. It is a `Vec::with_capacity` hint with no functional consequence and no observable, so no card can assert it either way.

**B10 — 0.6's `Op::Elementwise` literal does not compile.** Quoted: *"`Op::Elementwise { body: ScalarOp::Identity, operands: [(src, affine identity)] }`"*. Refuted by `proxima-tensor/src/op.rs:191-196`: the variant is `Elementwise { dtype: DType, body: ScalarOp, operands: Vec<(NodeId, IndexMap)>, name: Option<String> }` — `dtype` and `name` are required and `operands` is a `Vec`, not an array of a prose placeholder. The same omission is in 6.1's `cache_slot : Op::Iota { extent: Extent::Symbolic(1) }` against `op.rs:229` `Iota { dtype: DType, extent: Extent }`.

**B11 — 10.3's kill is written against a state main does not have.** Quoted: *"run the omega `metal_vs_cpu` bench **for the first time**"* and *"The omega bench does not build under `--features metal` ⇒ that is the finding and fixing the registration is the card."* Refuted by `.github/workflows/proxima-tensor.yml:191-205` (a dedicated `omega-compare-bench` job whose comment reads *"Smoke-runs the incumbent bench so it can never again sit registered-but-unexecuted"*, running `cargo bench -p omega --features metal --bench metal_vs_cpu -- --quick`) and by `scripts/omega-gate.sh:34` (`cargo build -p omega --all-targets --all-features`).

**B12 — 0.6's window-cleanliness assertion cannot be observed.** Quoted: *"`readback_bytes == 0` inside the timed window (the assertion that proves the window is clean)"*. Refuted by `omega/src/metal.rs:2369-2373`: `READBACK_BYTES` is a monotonic counter incremented once per effective output in `finish`; the copy arm has an N-element f32 output, so it is nonzero by construction and no snapshot mechanism is specified.

**B13 — 7.1's `tile_dim` key breaks the alloc-tier clippy arm.** Quoted: *"add `[packed_row_block] rows_per_group, lanes_per_block, tile_dim` … route each through `resolve_int` + a cross-axis validator + `emit_sizing_consts`"*. Refuted by `omega/src/msl.rs:1029-1030` (`#[cfg(feature = "metal-tiled-gemm")] const TILE_DIM: usize = 8;`) read together with `omega/build.rs:99-104`, whose own comment states the generated const must be emitted only when Cargo reports the feature active *"keeping the private `generated` module free of an unreferenced (dead-code-linted) constant"*, and `scripts/omega-gate.sh:56` (`cargo clippy -p omega --lib --no-default-features --features alloc -- -D warnings`).

**B14 — the 41,943,040 activation term has no source.** Quoted: *"`+ 41_943_040   # activations+uniforms: R13 steady 4.163e9-4.1404e9 = 22.6 MB x1.85`"*. 22.6 × 1.85 = 41.81 MB ≠ 41,943,040 B (= 40.00 MiB exactly). The stated multiplier does not produce the stated constant; the constant is a round binary figure and the multiplier is its quotient rounded to three digits. The term is load-bearing in G8 clause 3, in 6.5's `ARENA_PEAK_BYTES` rollback trigger, in 10.2's memory kill, and in Q14.

# Residuals worth naming, not yet breaks

- **§IV's 4.3 row mixes measurement modes.** −29% is applied to R13's `44.450 ms` packed-row-blocked bucket, which R13 itself brands per-op-mode with **+7.3% inflation**, and the result is subtracted from a *batched* `gpu_exec_ms` of 56.93. Deflating first gives 41.4 ms and a band of `[44.9, 48.6]`, not `[44.0, 48.0]`. The card instructs quoting the inflation beside every per-op number and then does not apply it to its own band.
- **4.3's −29% is a cross-tree transfer.** R12's feature-off control at 35.1 GPU *already carried the paired body* (the ledger says so), so 47.8→33.9 was measured on a tree whose GPU total was 35, not 57. The plan flags this inside 4.2's kill decomposition and still uses the number for the band; §XI.2's derivation sentence calls every term "carried from a MEASURED card delta", which is not true of this one until 4.2 runs.
- **3.3's coverage matrix arithmetic.** *"3 backends × 4 `BoundOpKind` (+ `Keep::Scan`) = **15 cells**"* — 3×5=15 holds only by counting `Keep::Scan` as a fifth kind, which it is not (`bind.rs:221-264`; `Keep` is a field of `Reduce`). The count is right; the cardinality claim beside it contradicts §II's "`BoundOpKind` stays 4".
- **`kernel_cache_key` is `pub(crate)` and `#[cfg(any(test, all(feature = "metal", target_os = "macos")))]`** (`msl.rs:730-732`). 3.1's N2 byte-stability test is therefore only reachable under `cfg(test)` or a macOS metal build — fine, but 3.1's N4 (*"the alloc-tier build compiles `route.rs`"*) and N2 are asserted from different build configurations and the card does not say so.
- **`entry_name(resolved: &BoundOp) -> String`** on main (`msl.rs:1690`, `wgsl.rs:538`, `cuda.rs:464`) takes no `Route`; 8.1 method 4 specifies `entry_name(&BoundOp, Route)`. Adding the parameter is fine, but it is a signature change inside the set 8.3's N1 requires to emit byte-identically, and no card states that the route must not enter the emitted name.
- **10.4 holds the single mutex through an ORT source build** with `--wait 5400` on every other card. Scheduling it terminal within Phase 10 bounds the blast, but any concurrently scheduled non-Phase-10 card exits 75 rather than queueing — G3's own failure mode, now a scheduling constraint the dependency graph does not encode.
