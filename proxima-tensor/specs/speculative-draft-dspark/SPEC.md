## problem

`speculative-decode-llama-parity` R11d requires proxima to gain DSpark speculation, which this sub-spec delivers as a Markov head and an optional confidence head carried as readout roots plus two metadata reads on the DFlash draft descriptor (no DSpark-named type), measured by the output of `draft-dspark` over our own trained draft equalling the target's plain greedy decode token for token on all 51 prompts of `speculative_corpus.jsonl` (gemma4 E2B, granite 1b).

## refutation condition

Written before evidence, two separate conditions (200 blocks, `p_min` 0.5 and the nonzero thresholds are pre-registered, plausible):

- Markov (R4, R8): across a 200-block corpus run on the E2B target with the trained draft, if no drafted token ever differs between "Markov bias computed" and "Markov bias skipped" (AC10 prints `markov_differing_blocks=0`), R4 is decoration. The control is AC11, the same run with the Markov weights zeroed, which must print `markov_differing_blocks=0`.
- Confidence (R5, R11): in the same kind of run with `--p-min 0.5`, if the gate never truncates a draft (AC13 prints `p_min_stops=0`) or no block's draft differs between "gate active" and "gate forced off" (`conf_differing_blocks=0`), R5 is decoration.

Either condition firing strikes the part it names (R4 or R5); it does not strike the other. If both fire, DSpark collapses into DFlash's sub-spec as one metadata flag and this sub-spec is struck.

## architecture

Nothing here is a new type. DSpark is the DFlash draft descriptor (`speculative-draft-dflash`) plus, when `markov_w1.weight` exists, extra head readout roots (`decode-as-data` R5, "extra head roots"), mirroring llama.cpp's own `is_dspark` boolean on the shared struct (`common/speculative.cpp:948,963`) rather than a second class. Its row in the `decode-as-data` table is the DFlash row: "masked block on a draft descriptor | block | sample-and-match on the target | prefix".

- **descriptor (R2/R3)**: the Markov tensors and the two metadata keys are fields on the draft `ModelDescriptor` (`proxima-tensor/src/spec/descriptor.rs:130-296`) the DFlash sub-spec already extends, populated at load only when `markov_w1.weight` exists. The confidence head is optional. Plain borrowed tensor views, box-free, no new trait.
- **Markov and confidence roots (R4/R5)**: lowered by `build_forward` as head roots in the readout list; `Op::Input` carries the previous in-block token. After the block's raw logits are produced, the propose pipe adds the bias (R4) and, when a confidence head exists and `p_min > 0.0`, applies the gate (R5) before returning the draft. `sample_from_anchor` (R7) selects the loop's start index and length and is read once at bind time, never per call.
- **classification (R1)** is a pure function over parsed metadata and tensor names: dflash architecture without `markov_w1.weight` is DFlash, with it is DSpark.
- **lossless harness (RL1-RL5)**: the `speculative_lossless_corpus` example is created by `speculative-draft-eagle3` slice 1 and consumed here with `--drafter draft-dspark`.
- **ablation definition (R8, R11, AC10 to AC14)**: the `dspark_markov_ablation` example runs the target's plain greedy decode over the corpus prompts in file order (`--max-tokens 64` per prompt), and a block is one draft call made from the committed context at one decode position, one block per position starting at each prompt's first generated token, taken in prompt order and then position order until `--blocks` blocks have executed or the corpus is exhausted; 51 prompts at 64 tokens offer more than 200 positions, so exhaustion before 200 is a failure of the grep, not a pass. Both arms of a comparison draft from the identical committed context of the plain greedy decode, never from their own speculative loops, so their contexts cannot diverge. A block differs when the two arms return different token lists (a different length counts). `executed_blocks` is a counter incremented once per executed block; `p_min_stops` is a counter incremented where the draft loop breaks at the `p_min` comparison; `markov_differing_blocks` and `conf_differing_blocks` count differing blocks for the Markov pair and the gate pair respectively.

### decisions

| decision | chosen | why not the alternative |
|---|---|---|
| DSpark as descriptor data on DFlash's draft | extra head roots plus two metadata reads | a second program duplicates DFlash's KV injection and block batching (principle 1); llama.cpp itself dispatches DSpark through the identical struct |
| confidence-gate failure mode | typed error | llama.cpp hard-fails with `runtime_error` rather than silently sampling unconditionally (principles 14, 15) |
| `sample_from_anchor` source | GGUF metadata only, read once at bind | llama.cpp reads it only from the draft's metadata (`common/speculative.cpp:987-989`); a flag would let proxima diverge from the draft's own contract |
| correctness oracle | the target's own plain greedy decode, over the 51-prompt corpus; hand-derived worked examples for R4, R5, R7 | llama.cpp parity needs a llama-format DSpark pair and none exists for E2B or granite 1b; the owner's direction is to train our own |
| optional `markov_w2.scale` tensor | out of scope | llama.cpp creates it as `TENSOR_NOT_REQUIRED` (`src/models/dflash.cpp:130`) and passes it to the bias matmul (`:350`); R2 resolves no scale tensor, so a GGUF carrying one is outside this contract |

## out of scope

## risks

| risk | likelihood | what it costs | what we do about it |
|---|---|---|---|
| the trained Markov head learns a near-zero bias, so AC10 prints `markov_differing_blocks=0` | medium | the Markov refutation condition fires and R4 is struck (a near-zero confidence head strikes R5 the same way, separately) | that is a recorded result of the measurement, not a failure of the spec; AC11 keeps the measurement honest |
| the confidence head is optional upstream; a draft without it makes R5 and AC5 inapplicable at serving time | medium | R5 only gated by the worked example | AC5 and AC6 use hand-built weights, independent of the trained draft |
| granite's profile does not arm verify, so ACL3 and ACL4 cannot run | certain today | granite arms stay blocked | `speculative-draft-training` slice 9 owns arming it |

## context

### background

- sub-spec of `speculative-decode-llama-parity` R11d, which requires a sub-spec for `draft-dspark` (`COMMON_SPECULATIVE_TYPE_DRAFT_DSPARK`, `common/common.h:179`)
- proxima has no DSpark support: `git grep -ciE 'dspark|markov' -- proxima-model-interop/src proxima-gguf/src proxima-tensor/src` lists only the llama type name in `serving.rs` and `speculative_settings.rs`
- llama.cpp dispatches DSpark through the same struct as DFlash, `common_speculative_impl_draft_dflash`, constructed with `type = COMMON_SPECULATIVE_TYPE_DRAFT_DSPARK` (`common/speculative.cpp:2654-2658`)
- this sub-spec adds DSpark's two deltas over `speculative-draft-dflash` -- a semi-autoregressive Markov head that conditions each in-block token on the previous in-block token's identity, and an optional per-token confidence head that truncates the draft -- as extra head readout roots on the DFlash draft descriptor (`decode-as-data` R5, R6) plus two metadata reads
- no DSpark draft exists for gemma4 E2B or granite 1b, and the owner's direction (2026-10-12) is to train our own drafts, so correctness is one relation: speculative decoding with greedy acceptance is lossless, so its output must equal the target's own plain greedy decode token for token (incumbent ~ plain decode is an owner-stated premise this spec does not re-measure, then speculative == plain decode)
- it adds no technique-named type (`decode-as-data` AC9)
- thresholds stated in this spec (the 200-block count, `markov_differing_blocks`, `conf_differing_blocks` and `p_min_stops` >= 1, the `p_min` 0.5 in AC10 to AC14, `rejected_total` >= 1, the `p_min` values 0.5, 0.1, 0.7 in AC5, the `1e-4` tolerance in AC4) are pre-registered, plausible; none is derived from a source
