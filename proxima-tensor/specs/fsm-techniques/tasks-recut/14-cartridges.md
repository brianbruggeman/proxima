## design decisions the cards encode (each with its one-line why)

1. An import file is a sealed-block file with `base_position == 0` whose non-empty layers each hold `p` rows (its row count). Why: the import and export format is one format for entry spill and import file; no second format.
2. The file's `descriptor_digest` is `LoadedModel::block_file_digest()`, and a loader refuses a file whose digest differs. Why: rows computed for another bound program do not mean the same thing here. Limit, unmeasured: whether two checkpoints with equal bound programs and different weights produce equal digests (the digest is over the program text, not the weight bytes).
3. An import file stands in the id space as `p` placeholder ids (value 0) prepended to every request that loads it. Why: the prompt-cache trie, longest common prefix, rewind and checkpoint code all work on ids with one id per row; a per-entry "assembled prefix" field would touch each of them. Cost, unmeasured: the placeholders enter the repetition-penalty window and the drafters' history.
4. The cache key binds the loaded import files by content, never by path: `assembled_prefix` is an xxh3 over, for each loaded import file in order, its payload hash (`content_key`) and its start row. Why: a path can be overwritten under a running server, and the placeholder ids are identical across import files, so the key is the only thing that keeps two import file sets apart.
5. The load stage runs only when no prefix was taken, and a prefix stage may not follow a load stage. Why: a taken prefix already holds rows that begin with the import file (it was stored under the same key), so loading again would double them.
6. A later load stage starts where the previous one ended (`held.moved.last().run.new_end()`) and its keys are rotated by `delta_rotations(serving_config, start)` through `rotate_rows`. Why: that is the only re-rotation primitive; a key stored at position `q` is `R(q) k`, and one more rotation by `start` gives `R(q + start) k`; values are never rotated.
7. An import file covers a ring (sliding-window) layer only when `p` is at most the window. Why: the file holds `p` rows per layer or none.
8. The loaded rows are not cache reuse: the report stays `CachePath::Miss` with the prefix stage's miss reason, `reused_tokens == 0`, and `prefilled_tokens` excludes the loaded rows. Why: no cached entry served the request, and a new `CachePath` variant would add public surface for one telemetry label.

## designs abandoned

- A separate per-entry field for the assembled prefix instead of placeholder ids (touches the trie, lcp, rewind and checkpoint code, all keyed on ids).
- Loading through `generate_from_prefix`: it never reaches the prompt cache (`cacheable` requires `seed.is_none()`), and `PrefixState` has `pub(super)` fields so no caller outside `generate` can build one from rows.
- The path as the cache-key component (overwrite hazard).
- A `concat_import_files` merge function that appends the planes of two import files into one run: two load stages each place their own run, so a merge function would be a second way to do what the stage list already does.
- A new `CachePath::Loaded` variant (see decision 8).
- Prewarm handling for import file keys: none is needed. `prewarm.rs::prewarm_queued` (~line 340) compares the job's key with `cache_key(..)` (which carries no assembled prefix) and skips a mismatch, so an end-of-answer prewarm queued under an import file key is skipped and cannot build rows from placeholder ids. No card in this slice exercises that skip; it is read from the code, not measured.
