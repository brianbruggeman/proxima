# coreml-ane-lane

status: audited
owner: Brian Bruggeman
created: 2026-10-11

Owner direction, 2026-10-11: omega lowers into the NPU; the Apple Neural Engine is the only unused hardware on this Mac, reached only through Core ML. Frame: one generic IR (proxima-tensor's algebra, lowered by omega) with many doors; every door is a proxima pipe over an FSM of its stages; generic (no per-model code); meet or beat the incumbent per door and cell. Binding invariant, verbatim: "these should have all of the same shape: just an fsm x sans-io for omega to build the format." A format is two sans-IO pipes (program to bytes, bytes to program) and gets no FSM, no stage enum and no door type of its own.

## problem

omega cannot execute a lowered program on this Mac's Apple Neural Engine: through one door pipe whose stages are the same FSM type the ONNX door runs on (parse, validate, lower, emit, package, verify, plan, execute), omega must write a Core ML ML Program (the MIL protobuf of `MIL.proto` inside an `.mlpackage`) from the lowered program of BAAI/bge-small-en-v1.5 (`onnx/model.onnx` at Hugging Face revision `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`, sha256 `828e1496d7fabb79cfa4dcd84fa38625c0d3d21da474a00f08db0f559940cf35`), compile it with `xcrun coremlcompiler`, load it through the Core ML framework from Rust with compute units pinned to `cpuAndNeuralEngine` and to `all`, and predict, such that over the 64-sentence corpus at batch 1 and batch 32 every L2-normalized CLS embedding is within max abs 3e-3 and cosine 0.9995 of the output tract-onnx 0.22.4 recorded on the same input tensors, the median ms per sentence in each of the four cells (batch 1 and 32 by `cpuAndNeuralEngine` and `all`) is at or below the median of Apple's coremltools-produced `.mlpackage` of the same model executed through the same Rust predict edge plus max(MAD, 2%), the peak RSS of each cell is at most 500 MB, and the first two layers of gemma4 E2B cut from its lowered program by `partition_at` execute on the ANE ahead of the Metal remainder with positional token agreement against the recorded llama ids no more than floor(0.02 x 164) positions below the all-Metal run's own count in the same run.

## refutation condition

Any one of these refutes the lane as a place omega runs work:

1. a sentence of the 64 whose embedding exceeds max abs 3e-3 or falls below cosine 0.9995 against tract's record, at batch 1 or 32, on `cpuAndNeuralEngine` or `all` (AC7);
2. a `bound metric=ms_per_sentence` line with `within=false` in any of the four cells, or a `bound metric=rss_peak_mb` line against the 500 MB cap with `within=false` (AC10, AC11);
3. the MIL census (R2) of the lowered bge-small program reporting `refused` above 0, or the compiled model carrying a `matmul` count other than 96, the number of MatMul nodes in the model bytes (AC2, AC4);
4. the `MLComputePlan` of the bge-small program under `cpuAndNeuralEngine` placing zero operations on the Neural Engine: the arm is then VOID and the lane puts nothing on the ANE (AC6, AC7);
5. the coremltools incumbent's own embeddings exceeding the lane tolerance against tract: the pre-registered tolerance is then unreachable at fp16 and every parity row is void (AC17);
6. the gemma4 E2B front census reporting `refused` above 0, or its token agreement falling more than floor(0.02 x 164) = 3 positions below the all-Metal count (AC14);
7. mnist.onnx needing any model-specific branch in the lane (AC16);
8. Core ML serializing the ANE predict behind the Metal queue: the `bound metric=gpu_ms` line with `within=false` (AC13).
9. the emit hot path allocating (AC20 above 0 allocations) or `proxima-mil` failing its tier-1 build (AC19 with N=0 or a red case): the writer is then not the sans-IO primitive this spec claims.

The premise "the lane emits MIL text that `coremlcompiler` compiles" is already refuted on this box (see "verified on this box"): the model document is protobuf, and the lane emits that.

Oracles, none sharing code with the path under test: tract-onnx 0.22.4 recorded as `omega/tests/fixtures/bge-small/tract_b1.jsonl` and `tract_b32.jsonl`; Apple's coremltools as the incumbent producer, with its package sha256-recorded and its embeddings recorded once; `protoc` as an independent decoder of the emitted `Model.proto` bytes; `xcrun coremlcompiler` as the independent validator of every operator name and parameter; the recorded llama ids under `proxima-model-interop/tests/fixtures/llama-parity/gemma4_e2b/`; the real MNIST `t10k` labels; the hand-computed two-layer-MLP softmax values at `omega/tests/onnx_metal_parity.rs`; the card 1.1 summary lines for the dispatch floor. Python is never part of a proxima gate; coremltools has no command-line tool, so its single conversion call is made once by a recorder outside proxima and the result is recorded as files (see the incumbent decision).

Controls, by kind of check. A comparison against a recorded or vendored external file carries an identity control (the record compared to itself through the same function passes) and a degenerate control (a copy altered in one place fails). A comparison against a hand-derived value carries a degenerate control. A structural assertion against a constant stated in its own AC carries none. Each control is a counted test case inside its AC.

### the door, generalized

One FSM serves every format; a format contributes pipes, never stages. The stage enum is the union of what any door does; an instance enters only the stages its pipes need and the transition table skips the rest.

| stage | ONNX in, CPU or Metal out | ONNX in, Core ML out (this lane) | E2B front in, Core ML out |
|---|---|---|---|
| Parse | `parse_complete` | the same | `partition_at` of the lowered program |
| Validate | census and pins | the same, plus the MIL census (R2) | the MIL census |
| Lower | `lower_graph_pinned_decoded` | the same | passed through |
| Emit | not entered | `MilWriter`: program to MIL `Program` | the same |
| Package | not entered | `MilWriter`: `Program` and weights to `MilPackage` | the same |
| Verify | not entered | edge: `coremlcompiler compile`, compiled operator count | the same |
| Plan | `plan_named` | edge: load `MLModel` with the configured `ComputeUnits`, keyed by pin set | the same |
| Execute | `execute_plan_named` | edge: predict | the same |

An instance without a writing pipe never enters Emit, Package or Verify, and an instance fed a lowered program (the front) has no Parse of its own: the door type is the same, the transition table skips the stages an instance has no pipe for. `xcrun coremlcompiler` and the Core ML framework are outside the pipes: they are the edge the Verify, Plan and Execute stages call, as `plan_named` is the edge to Metal today.

| Negate | `mul` by a constant -1 | MIL has no `neg` (compiler: `Unknown operator 'neg'`) |
| Reciprocal, Exponential, Logarithm, SquareRoot, Tanh, Erf | `inverse`, `exp`, `log`, `sqrt`, `tanh`, `erf` | `inverse` and `log` carry the required `epsilon` |

### decisions

| decision | chosen | why not the alternative |
|---|---|---|
| what the lane emits | the MIL `Program` as protobuf inside `Model.proto` (`mlProgram`), in an `.mlpackage` | MIL text: the compiler rejects it as a model document (wireType error above); the text exists only as compiler output. The compiled `model.mil` is read back as the independent census of what was emitted |
| ML Program, not the neural-network format | `mlProgram` | the card 0.1 harness wrote `NeuralNetwork` layers (`inner_product`); that format has `model.espresso.*` and no `model.mil`, and cannot express the 41 operators above |
| where the lane enters omega | as a Sink of the generalized door, with `compute_units` in `DoorConfig` | `Engine::Npu`: `backend.rs:91-96` deleted the `Npu`/`Ane` reservations because they had no lowering, and `plan_named` (`backend.rs:413`) has no compute-unit parameter, so a variant would thread a parameter through every caller for one lane; the door already owns config, stages and the plan cache |
| one FSM for all formats | the one generic `Door` (the shape is `mlir-interop` slice 1's decision under its AC1 and AC14) | a per-format stage enum (`OnnxDoor`/`MilDoor`): the owner's invariant forbids it, and the ONNX door's cache, error and walkthrough would exist twice. The cost is three more `DoorStage` variants that the ONNX instance never enters, proved by test |
| composite MIL operators (`layer_norm`, `softmax`, `gelu`) | not emitted from a recognized fragment | the positioning in `TODO.md` ("never recognize a familiar fragment"): the lane maps the algebra's forms; a decomposed softmax is `exp`, `reduce_sum`, `real_div`. Whether the ANE places the decomposition well is measured in AC6 and AC10, not assumed; a rule over the algebra that fuses by structure is a later slice if the trace names it |
| contraction to `matmul` | classified by `IndexMap` structure | emitting `mul` then `reduce_sum` materializes the product tensor (batch x seq x 384 x 1536 floats) and is a rewrite-free but ANE-hostile form; the classification is the algebra's own definition, so a single-op synthetic test fixes it |
| precision | fp16 interior, fp32 I/O | the ANE computes fp16 only on M1 (`docs/research/npu-lanes-census-2026-10-08.md`); fp32 I/O keeps the door's `DoorBatch`/`DoorOutput` unchanged |
| static shapes | one program per pin set, cached by the door's pin-set cache | the ANE takes static shapes; the door already keys plans by pin set (`onnx-door` R5), at most 4 pin sets per cell by the padding rule |
| compute units | `cpuOnly`, `cpuAndNeuralEngine`, `all` | there is no ANE-only unit in the API; `cpuAndNeuralEngine` allows CPU fallback, so the fraction of operations `MLComputePlan` places on the Neural Engine is the measured quantity, and a cell with zero is VOID. `cpuAndGPU` is omitted: card 1.1 showed Core ML places the linear on CPU under it (0.2337 ms) |
| incumbent | Apple's coremltools-converted package of the same model at the same static shapes, fp16, executed through the same Rust predict edge, interleaved with the lane arm per iteration | a timing from coremltools' own Python predict: it would measure a different edge. The package is produced once by a recorder in the indexer repo, outside proxima, because coremltools ships no command-line tool: the one place the owner's "run the tool as a binary" cannot be met literally; the conversion arguments and package sha256 are recorded and nothing Python runs in any gate |
| tolerance | max abs 3e-3 and cosine 0.9995 per sentence, pre-registered, status plausible | fp16 compute against tract's f32: the f32 Metal chain was held to 1e-3 (`onnx-door` R9); three times that for fp16 storage and accumulation is a guess until AC17 records the incumbent's own error against tract. A failing number is reported, not widened |
| weights | written once from a source view (the ONNX initializer `raw_data` slice, or a GGUF tensor view) into the blob buffer, converting to fp16 in the same pass; the door's shared f32 decode (`decode_initializers`) is not used on the MIL path | a decoded f32 copy per pin set breaks the 500 MB cap (`onnx-door` risks) and a second copy is the allocation R20 forbids |
| compile cache | `.mlmodelc` cached by package sha256 under `$HOME/.cache/proxima/coreml-lane/` | compiling per door construction repeats a multi-second step; the cache key is the content, so a changed program recompiles |
| GPU lock | every slice that loads a model on the ANE holds `/Users/brianbruggeman/repos/slot-0/.long_ctx_backups/gpu.lock` | the box is shared and card 3.1's concurrency arms need the GPU quiet; compile-only and sans-IO slices do not |

Designs ruled out while writing this: a per-format door; emitting MIL text; the `Engine::Npu` variant; fusing softmax and layer norm by name into composite MIL operators; reusing the card harness's neural-network proto path; timing the incumbent through coremltools' Python predict; `prost` for the writer; a `mil` module inside std-bound omega; a decoded f32 weight copy on the MIL path.

### the guiding-principles audit (applied before the design; what each constraint changed)

| principle | what it forced here | design abandoned because of it |
|---|---|---|
| internal-primitive audit (RISC reuse) | the MSL, WGSL and CUDA emitters (`omega/src/msl/mod.rs`, `omega/src/wgsl.rs`, `omega/src/cuda.rs`) are the precedent for "omega renders a program for a back end as text compiled by the vendor toolchain"; what is shared is the input (`proxima_tensor::Op` and `IndexMap`) and the `NumericPolicy`; their `String` builders share nothing with a protobuf writer, and they live in std-bound omega, so the MIL writer is its own crate that can build at tier 1 | a `mil` module inside omega beside `msl`, which would force std on the writer |
| the Core ML bindings audit | `git grep objc2-core-ml origin/main` finds no use: the card harness that used it is unlanded (patch `0002`); the only objc2 family in the tree is objc2 0.6.4, objc2-metal 0.3.2 and objc2-foundation 0.3.2 (`omega/Cargo.toml:577,590,614`); `objc2-core-ml` 0.3.2 is the same generation, added once by `cargo add`, and the card harness's compile, load and `MLComputePlan` code is the starting point of `coreml/model.rs` | a second Objective-C binding crate, or a hand-written `objc_msgSend` layer |
| no_std and no-alloc | the wire encoder writes into `&mut [u8]` and returns a length; a too-small buffer is a typed error, so the buffer size is a decision the caller makes with `measure()` (the fixed-capacity forcing the guiding principles name) | `prost`: its messages allocate per node, its `map` fields default to `HashMap` (std), and `prost-build` needs `protoc` at build time; the hand encoder is checked by `protoc --decode` as an independent oracle |
| zero-copy | weights are written once from a source view (the ONNX initializer `raw_data` slice of the model bytes, or a GGUF tensor view) into the blob buffer, converting to fp16 in the same pass | the door's decoded f32 initializer `Vec` on the MIL path (it stays for the CPU and Metal instances) |
| lock-free first | the plan cache is the door's single-writer cache; the Core ML handle lives in the execute edge and is owned by the cache entry; the writer holds no state across calls | a shared `Mutex<HashMap>` of loaded models |
| config and fluent builder | `compute_units`, `precision` and `model_cache_dir` are `DoorConfig` fields with a builder and a loader proven equal | environment-only lane switches |
| no magic numbers | the 1 GB graph ceiling (a community figure, `docs/bench-campaigns/2026-10-08-ane-lane/plan.md` card 1.3), the padding multiple 16 and maximum 64, the specification version 7, the opset `CoreML6` and the default compute units are keys of `proxima-mil.toml`; AC12 replaces the ceiling by a measurement | constants in source |
| box-free, RPITIT | the door's `Pipe::call` is already RPITIT; the writer is a plain function behind `Pipe`; no `Box<dyn>` | a boxed sink trait object |
| the evidence ladder (P18, P19) | every perf cell carries its mechanism column (placement from `MLComputePlan`, CPU %, GPU sampler) next to the number; a number alone is a measurement | reporting ms per sentence without placement |

### sans-IO alloc budget (R20)

| path | allocations | how it is enforced |
|---|---|---|
| hot: `emit_node` for one mapped node, `write_weight` for one tensor | 0 | counting allocator over a 100k-iteration loop (AC20) |
| setup, per program: `MilWriter::call` | exactly 3 buffers (model, weights, manifest), sized by `measure()` | AC20 case on two program sizes |
| census: `MilCensus.refused` | one `Vec` growth per refused node | cold path; empty for a program that maps |
| cold: error paths, the door's parse and lower stages | unbounded, as in the ONNX door | not claimed |

Tier ladder: `wire.rs` and `weights.rs` are `core`-only (tier 3 candidates, no `alloc` import); `census.rs`, `writer.rs` and `sized.rs` need `alloc` (tier 1); `proxima-mil` has no tier-2 module, because `xcrun` and Core ML belong to the edge in omega.

## out of scope

- the exact top-k router on the ANE: `docs/bench-campaigns/2026-10-08-ane-lane/plan.md` row 6.3 is pre-killed (top-k, gather and scatter unsupported on the M1 ANE) and the CPU predictor at 81.5 us beat the ANE floor; the tiered warm/cold expert design is a separate spec
- the route predictor on the ANE (cards 5.3 and 5.4) and the speculative draft head (card 6.1)
- training graphs, and quantized compute on the ANE: weights go in as fp16; palettization and W8A8 (A17 Pro and M4 only) are not used
- Hexagon, XDNA, Intel NPU and LiteRT lanes: census only, in `docs/research/npu-lanes-census-2026-10-08.md`
- the private ANE API (`_ANEClient`): not shippable
- MIL text as an input format (refuted above) and a MIL text reader: the compiled `model.mil` is only read back for the census
- a reader pipe from `.mlpackage` bytes to a program (the reverse direction of this format)
- other doors (GGUF, safetensors, MLX, MLIR): this spec is the Core ML sink and the door generalization it needs
- an in-process incumbent for the emitter itself: coremltools' serializer is Python and cannot run in a gate; the end-to-end incumbent arm is AC9
- changing tolerances or bounds after a measurement; a failing number is reported, not widened
- IOSurface zero-copy handoff between a Metal buffer and a Core ML input (card 1.2): the front's handoff here is a host copy, measured inside AC15
