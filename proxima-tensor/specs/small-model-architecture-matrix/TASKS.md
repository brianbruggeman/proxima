# small-model-architecture-matrix -- implementation cards

Each numbered row is one semantic commit and bisect point capped at 30 minutes from first file read through its acceptance command and TASKS update. If a row cannot fit, split it before coding and update the ledger count. The listed commands are acceptance interfaces to implement in the named cards; they do not claim unimplemented tests, validator modes, examples, or checkpoint trials already exist. Each Rust filter selects one named test that prints and asserts the listed payload counts. The owner authorized each card as a coherent commit pushed to origin/main; run the acceptance command and update this ledger before each commit.

All eleven pinned cases remain distinct. The ten public text-capable cases receive the same ant, hippo, soliloquy, and paris payloads from `gemma4_ring_parity.rs:119-155` plus one hand-checkable coding prompt. LFM-VL and LFM-Audio each add a modal request. Sori contributes one access record; it has zero Proxima request invocations or numeric oracle until its gated bytes are readable. Gemma 4 E2B adds five text requests plus image, audio, and video requests. Thus the request ledger has 56 records: 55 public-model trial attempts and one Sori access record. Every record carries repository/revision, checkpoint/config hashes, exact input IDs or modal bytes/hash and decoded input, load/bind and invocation statuses, output/error payload, semantic rubric/status, numeric boundary/reference/status, and upstream runtime/revision. Typed failure is explicit evidence, not an omitted row or an execution claim. Each public model also retains one tokenizer-verified, full-request prefill measurement on a fixed owner prompt; the Sori access row has none. A prefill measurement contains raw repeated timings, throughput, p50/p90/p99/p99.9 latency, one real-client request latency, CPU utilization, steady and peak RSS, error count, coefficient of variation, host/device/loadout, checkpoint and tokenizer hashes, and the output/correctness gate.

Checkpoint topology is parsed from the pinned config and verified against tensor names/shapes. Conflaguration, serde, environment, file, and fluent builder describe legal execution variants only. Card 7's semantic pair matrix tests sharing by actual operator/state equations; two reuse pairs and four distinct pairs require positive vectors and wrong-substitution controls, with each pair citing exact upstream/local artifacts. If those facts do not support the proposed pair, change the matrix before using it to justify an abstraction. Full graph trial cards require actual Proxima calls. The retained Granite 3.1 1B Q8_0 SharedK result is an isolated attention-dispatch replay: SharedK took longer in all 40 paired samples at tokenizer-verified 256/972-token shapes, with every signed SharedK-minus-legacy duration positive (`proxima-tensor/specs/granite-attention-variant-performance/TASKS.md:9`). It does not establish whole-request Granite 4 prefill performance. Granite 4 prefill cells use the pinned `ggml-org/llama.cpp` commit `f1ea206218210afb913ae2f5d2c51faed35915da` and the same official BF16 GGUF bytes in both runtimes: Micro repo revision `4a6c034845e314924ab1e64e183a1454ff1ea159`, `granite-4.0-micro-base-bf16.gguf`; H-Tiny repo revision `27f75056a8aabab6377df1d9dd4f37c9b1fbe14`, `granite-4.0-h-tiny-base-bf16.gguf`. Dispatch optimization cards change only `AttentionVariant.tile_height`, comparing `Legacy` with `Rows16` and defaulting every other selector. Keep an optimization only if the forward and reverse raw cells and output gates support it. The trial runner reads revision pins from `inventory.jsonl` and a caller-provided checkpoint store; it does not commit weights.

Card 7 starts from these **candidate** pairs; the expected result is an acceptance target, not a finding. Each pair record must name both exact pinned config keys, the upstream operator implementation, the local operator/state contract, and compared input/state/output vectors. Reuse means the same inner operator and state equation after checkpoint-specific pre/post transforms are represented separately.
