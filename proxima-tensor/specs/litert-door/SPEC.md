# litert-door

status: audited
owner: Brian Bruggeman
created: 2026-10-11

Owner direction, 2026-10-08 and 2026-10-11, verbatim where quoted. LiteRT joins the door list (`TODO.md`, "Interop doors"). Frame: one generic IR (proxima-tensor's algebra, lowered by omega) with many doors; every door is a proxima pipe with an FSM over its stages; generic (no per-model code); meet or beat the incumbent per door and cell. Binding for this spec: "for tflite and maybe litertlm if it's not open, then I want to ir lower to that format and just compile with their tooling" (export first); "these should have all of the same shape: just an fsm x sans-io for omega to build the format" (one door FSM in omega, a format is two sans-IO pipes); "for litertlm, we should rebuild that in omega then - an implementation with our favored approach (fsm x sansio | pipe | fsm x sansio... all the nostd, noalloc, zerocopy, zerolock, etc. from /guiding-principles and /disciplined-component)" (the readers and writers are a disciplined component).

## problem

omega cannot yet write the granite3.1-moe:1b lowered decode program (GGUF `library/granite3.1-moe:1b`, sha256 `cd60b3e8bb445d4c05e0b0b99b1bb41e8bb77211b161e783c71931168131df80`, `bind.ops=5602`, `bind.ops_sha256=d6e74983139982a001f3595dc9859da168e6691f409757b96550e486dbb889d1` at `proxima-model-interop/tests/fixtures/llama-parity/granite_moe.digest`, pinned at 5, 7 and 72 prompt tokens for the 3 prompts of `granite_moe/llama_ids.json`) as a `.tflite` FlatBuffer and as a `.litertlm` bundle through one format-generic door FSM built from two sans-IO pipes per format, such that Google's LiteRT runtime (`benchmark_model` built from LiteRT tag v2.3.0, commit `4352e261d3f1b3cda00345db5dbd75859d3bf0d3`) loads the `.tflite` and returns logits within max abs 1e-3 of omega's CPU logits with a top-1 token equal to llama.cpp's recorded first generated id on all 3 prompts, LiteRT-LM v0.18.0's `litert_lm_main` loads the `.litertlm` and generates text beginning with llama.cpp's recorded text, omega reads Google's `Gecko_64_f32.tflite` (sha256 `31e402e85fd0f45ec82588939ba1f0424c1366b17dbe8a6cd431007bfeefabe3`) on CPU and Metal to within 1e-4 and 1e-3 max abs of LiteRT's recorded embeddings over 64 recorded sentences, and in each of the four cells (export at 5, 7 and 72 tokens; import at batch 1) omega's median time per inference and peak RSS on `Engine::Cpu` and on Metal are at or below the best recorded LiteRT arm (median plus max(MAD, 2%)), with the reader and writer pipes held to the disciplined-component gate (default-off feature, tier builds with asserted module counts, zero allocations over a 100k-iteration hot loop, no lock types, sizing config, config and builder parity, a re-provable discipline log).

## refutation condition

Any one of these refutes the door as present and viable:

1. a granite pin set whose logits exceed 1e-3 max abs (CPU) or 5e-3 (Metal) against LiteRT's recorded run, or whose argmax differs from the `generated_ids[0]` of the matching entry of `llama_ids.json`;
2. LiteRT's loader rejecting a `.tflite` this door wrote, or `litert_lm_main` rejecting the written `.litertlm` (the run record's exit code is nonzero), or the vendor loader accepting the corrupted-offset control;
3. the census (R1) naming an op form of the granite program that has neither a builtin mapping nor a typed refusal, or the qwen3.5 program (R21) needing a model-named branch;
4. a `bound` line with `within=false` (R19, R20);
5. the door FSM needing a format-named branch (AC2's format-name counter), or any of the ONNX door's 16 landed tests changing an assertion;
6. our reader's operator, tensor or buffer counts for `Gecko_64_f32.tflite` disagreeing with the counts recorded by the LiteRT tool (`model_runtime_info`) or by the independent FlatBuffer bindings (R14): the reader would be wrong and every import row void;
7. any hot loop of R26 allocating, or any tier build of R25 compiling zero modules.

Oracles, none sharing code with the path under test: the LiteRT runtime (`benchmark_model`, a vendor binary run once, its outputs recorded as files, never re-run in a gate); Google's LiteRT-LM packager `litert-lm-builder` and `litert-lm-peek` 0.18.0 (PyPI console scripts, vendor tools run once, outputs recorded; we write no Python) and the `litert_lm_main` release binary; llama.cpp's recorded ids (`granite_moe/llama_ids.json`, llama commit `f1ea20621`); the FlatBuffers internals document (hand-encoded worked examples); ggml's `block_q8_0` and `block_q4_0` layouts; the TFLite schema comments (`f = scale * (q - zero_point)`); the independent Python FlatBuffer bindings used once while writing this spec to count `Gecko_64_f32.tflite` (the counts below). No correctness oracle is proxima's own output; the `*.digest` and `*.bound` fixtures are consistency baselines (determinism checks, labelled as such in the AC) and decide nothing about correctness.

Controls, by kind of check. A comparison against a recorded or vendored external file carries an identity control (the record compared to itself through the same comparison function passes) and a degenerate control (a copy altered in one place fails). A comparison against a hand-derived value carries a degenerate control (the expected value altered fails). A structural assertion against a constant stated in its own AC (a count, a shape, a file name, a hash) carries none, except a source-scanning counter, which carries a counter control (a string containing the scanned word returns 1). Each control is a counted test case inside its AC.

## requirements

Each R is one consumer-visible behaviour; its single AC enumerates the named test cases that exercise it. The Rs fail independently of one another: each has a different producer module, a different recorded file, or a different measured quantity. Export (omega program to `.tflite` and `.litertlm`) is the headline; import follows it; the disciplined-component gate closes the list.

### the shape

```
read  : bytes --[format read pipe: parse, validate, lower]--> Program --> plan --> execute          (Door FSM: Read, Planned, Executed)
write : Program --> lower(pins) --> [format write pipe: emit] --> Segments --> package --> verify   (Door FSM: Lowered, Emitted, Packaged, Verified)
```

`Door<Read, Write>` holds the two pipes as generic parameters bounded by `Pipe`; there is no `Format` trait and no per-format door. Read failures carry a `StageKind` tag set by the reader pipe's own steps (Parse, Validate, Lower), so `DoorError::stage()` keeps returning the five ONNX stage names the 12 landed contract tests assert. Write stages: Lower binds the pin set and weights, Emit calls the writer pipe and yields byte segments (owned FlatBuffer bytes plus segments borrowed from the program's bound weights), Package is the I/O edge that places the segments at their offsets in the destination, Verify is the vendor edge. The vendor toolchain (`benchmark_model`, `litert-lm-peek`, `litert_lm_main`) is outside the pipe: the edge that loads or runs the bytes, and the recorded incumbent. The read-side plan cache, keyed by pin set, is the landed single-writer cache (`omega/src/onnx_door/cache.rs`) moved with the module; the write direction is pure and caches nothing.

The program value crossing the door is the landed `Lowered` content (`proxima-onnx/src/lower.rs:170`: program, inputs, graph outputs, named weights) minus its ONNX-only `matmul_names` side table, with weights as the named `QuantizedBlock` list the plan already takes (`omega/src/onnx_door/stage.rs` `named_blocks`) in place of f32 vectors. A new type is added only if slice 1's two-call-site test shows no existing type serves: `Lowered` fails the dependency direction (it lives in `proxima-onnx`) and `BoundProgram` (`proxima-model-interop/src/lowering.rs:115`) fails it too (it needs the GGUF binding crate).

## out of scope

- the LiteRT NPU and GPU delegates themselves as omega lanes (vendor NPU paths, Android builds); the CoreML ANE lane spec covers this box's NPU
- training, TF SavedModel, `.task` (the `PK` zip container, `file_format_util.cc:45`)
- custom operators and FlexBuffers `custom_options`, sparse tensors, FLOAT8, INT2, VARIANT and RESOURCE tensors
- LiteRT-LM vision, audio, embedding and drafter sections on the write side (the reader enumerates all 12 sections of the Gemma bundle; the writer emits 3)
- models whose FlatBuffer exceeds 2 GiB (typed refusal; the `Buffer.offset`/`size` external form, `schema.fbs:1690`, is not written)
- dynamic shapes (`shape_signature`) and data-dependent control flow
- the `ai-edge-litert` Python wheel and any Python in a gate; the vendor Python console scripts run once outside it
- any proxima dependency on LiteRT, TFLite, `flatbuffers`, `planus` or `flatc` (R23)
- changing tolerances or bounds after a measurement; a failing number is reported, not widened
- other doors (GGUF, safetensors, MLX, MLIR); this spec is the LiteRT door only

## risks

| risk | likelihood | what it costs | what we do about it |
|---|---|---|---|
| the granite program holds op forms with no builtin or a rule that needs a materialized outer product (MoE routing) | medium | R7 refusals; R10 cannot run | the census (R1) counts them first; each rule is a structural predicate over maps with a hand-derived example, never an architecture branch; a form with no faithful builtin stays a typed refusal and the cell reports it |
| LiteRT dequantizes constant INT8 tensors to resident f32 at load (5.5 GB for granite) | medium, unmeasured | R20 reports a loss against the best LiteRT arm only if omega is larger; a LiteRT win on time with a loss on memory is two separate lines | R20 records the LiteRT RSS column; the writer's `quantization` option can write f32 instead, measured as a separate arm |
| omega's packed Q8_0 matmul quantizes activations while LiteRT multiplies dequantized f32 | medium | R10 misses 1e-3 | the per-position max abs is printed; the control binds the same weights as f32 in omega (`NumericPolicy` is a door config field) before any tolerance discussion |
| `litert_lm_main` requires the signatures and cache tensor names Google's converter emits for `tf_lite_prefill_decode` | high | AC12's run case fails and the bundle is a valid container with a model the runtime refuses | the first measurement of slice 15 reads the signature requirements from LiteRT-LM's executor sources and records them in the fixture README; the writer emits those signature names from the program's inputs and roots by rule; if the runtime still refuses, the recorded message is the finding and R12 stays open |
| `benchmark_model` has no prebuilt binary and the CMake build fails on this box | medium | R9 and every vendor record blocked | the build is a recorded one-time tool step in the indexer repo; failure is the next task (fix the build flags), not a stop |
| the `Inference (avg)` of 5 invocations is the only per-run sample the tool prints | medium | MAD over 5 samples is coarse | R18 uses the 5 invocation values with CoV; `--num_runs=1 --min_secs=0` per invocation |
| the Gecko corpus needs SentencePiece tokenization and proxima-tokenizer has no SentencePiece reader for this model | medium | R15 corpus missing | the indexer repo tokenizes once with the pinned `sentencepiece.model` (SentencePiece's own encoder as a vendor tool) and the proxima side validates the ids file; 64 int32 ids per sentence |
| the Gemma bundle is 2.6 GB and the Gecko files 441 MB | low | slow tests | only hashes and headers are vendored; the files are opened from the Hugging Face cache layout and the tests fail with the path and an env override when absent |
| a hot-loop allocation hides in a typed error path | low | AC26 fails | the reader and writer cores return `Result` over `Copy` error variants; the counter test names the failing loop |
| the LiteRT-LM head schema moves past the pinned tag | high over time | the reader meets a 13th section type | the reader returns a typed `UnknownSectionType` and the discipline log carries the head diff as a forward note |
| tier-3 caps from `sized` are too small for the 5602-op granite program | high | tier-3 writer refuses | the default caps serve the tier-3 hot-loop fixtures; the tier-1 path grows to the program; both documented in the toml |
