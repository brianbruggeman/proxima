# proxima-nova

status: audited (c1 scope, PROXIMANOVA-9 round 3 ADMIT 2026-11-20); c7-c11 reuse map added after the audit
owner: brian
created: 2026-11-20
epic: PROXIMANOVA-1

## problem

proxima has 0 native-code emitters, so proxima-nova compiles rustc MIR to aarch64 Mach-O
through its own IR, with each stage a pipe run on prime and the whole driven by
`cargo-nova`; for c1, both entry points must run 2 of 2 fixtures (`ret42`, `ret7`) with
exit codes equal to the rustc+LLVM build of the same file.

## background

omega's 4 emitters produce MSL, WGSL, PTX text and Core ML MIL (`omega/src/msl/`,
`wgsl.rs`, `cuda_ptx_store/`, `door/sink_mil.rs`), and nothing in the workspace writes
Mach-O or ELF.

The compiler is driven by `cargo-nova`, an alternative to `cargo build`/`cargo run`. It
reads the manifest, plans the compile units, and spawns rustc with the nova backend, all as
pipes on prime. `cargo val` replaced nextest the same way, at a twentieth of its size.

Owner, 2026-11-20: "I want to build a compiler. a full compiler. I think we'll call it
proxima-nova", "basically, I want to build a rust-ir compiler", "I want it to use the prime
runtime and I want it to use pipe primitives", "not just a ir, - like a full alternative,
maybe, to cargo as cargo-nova".

## refutation condition

Either of these shows the shape is wrong:
- the rustc adapter cannot hand a single MIR body to nova without re-running rustc's mono
  collection itself;
- ~~a stage cannot be written as a `Pipe` (`proxima-primitives/src/pipe/primitives.rs:91`)
  without a new library type.~~ Struck 2026-11-21 (card 48 audit, G1): the clause did not separate per-item stages from the object step, which is a fold.
- a per-item stage (one function in, one result out: lowering, isel and regalloc, encoding) cannot be written as a `Pipe` (`proxima-primitives/src/pipe/primitives.rs:91`) without a new library type.
  - The object step is not a per-item stage. It accumulates every function into one Mach-O, so as a `Pipe` it would need either the whole crate as `In` (the materialisation card 48 removes, R27) or interior mutability behind `Pipe::call(&self)` (`primitives.rs:101`), which is a lock.
  - It is therefore a sans-IO typestate fold (`ObjectBuilder`, R27), the same exception `ByteStreamParser` documents (`proxima-primitives/src/pipe/sans_io.rs:41-52`) and the house style's sans-IO state machines.
  - A fold type that also accepted per-item transforms would refute the shape.

## format matrix (c12)

Nova emits relocatable objects. Until c13 lands, the platform linker (ld64, GNU ld/lld,
link.exe/lld-link) produces executables and shared libraries while rustc packs rlibs and
rmeta; c13 replaces that dependency for nova's own objects, and the platform linker remains
only as the c13 control arm. The `object` crate (already a dependency, features `macho`
today) writes all three containers. `gimli` writes DWARF.

Per-format work beyond the container: relocation kinds differ per format and arch (Mach-O
`ARM64_RELOC_BRANCH26`/`PAGE21`/`PAGEOFF12`, ELF `R_AARCH64_CALL26`/`ADR_PREL_PG_HI21`,
COFF `IMAGE_REL_ARM64_*`/`IMAGE_REL_AMD64_*`), as do symbol naming (Mach-O prefixes `_`), TLS
models and section names. Two ISAs (aarch64, x86_64) cover all six targets.

Outside the six: `x86_64-pc-windows-gnu` (COFF + DWARF, MinGW), `wasm32-unknown-unknown`
(wasm object with a `linking` section), riscv64. Each is a row added later, not a branch in
the emitter.

## linker (c13)

Nova's objects are inputs to a linker nova owns. The first slice must replace the one external
tool the current fixtures use (`cc`, which calls ld64), not grow a general-purpose linker. L1
(the first card) links one `_main` with no data, stubs or libSystem; the stub and `LC_LOAD_DYLIB`
rows below arrive at L3, and the table's first column is the L1-L3 scope, not a single card.

| element | scope over the first linker cards (L1-L3) | later |
|---|---|---|
| inputs | nova Mach-O objects for aarch64; system library stubs from the SDK | static archives (`.a`), x86_64 objects, ELF and COFF inputs |
| symbol resolution | defined and undefined globals, one definition wins, undefined is an error naming the symbol | weak/weak-def/commons, archives resolved lazily in member order |
| layout | `__PAGEZERO`, `__TEXT` (header, `__text`, `__const`), `__DATA` (`__const`, `__data`), `__LINKEDIT`; 16 KiB pages; section alignment from the object | `__DATA_CONST`, per-function sections, dead-strip reachability |
| relocations | `ARM64_RELOC_BRANCH26`, `PAGE21`, `PAGEOFF12`, `UNSIGNED` (the four nova emits today: `pipeline.rs:18` plus the pointer slot at `object.rs:247`); every other kind refused by name, including `SUBTRACTOR`, which no source constructs | x86_64 kinds for c12's second ISA; subtractor pairs if a target needs them |
| external calls | stubs in `__TEXT,__stubs` + lazy or non-lazy binding for `_exit`/libSystem | GOT for data, weak imports |
| load commands | `LC_SEGMENT_64` per segment, `LC_MAIN`, `LC_LOAD_DYLIB` for libSystem, `LC_BUILD_VERSION`, `LC_SYMTAB`, `LC_DYSYMTAB`, `LC_CODE_SIGNATURE` (ad-hoc; arm64 macOS refuses to exec without it) | `LC_DYLD_INFO_ONLY` or chained fixups, `LC_UUID`, `LC_FUNCTION_STARTS` |
| output | an executable that runs with no `cc`, `ld`, `ld64` or `link.exe` process spawned | dylib, static archive, PDB |
| oracle | every binary's exit equals the rustc+LLVM build; `otool -l`, `otool -r`, `nm` and `codesign -v` agree with ld64's output | the same per format |

Not claimed by slice 1: dynamic linking of nova-produced dylibs, TLS, lazy binding, PDB,
LTO, `--gc-sections`, and any target whose encoder does not exist yet. The linker lives in
its own crate beside `proxima-nova` (working name `proxima-link`, a real package name at
admission) so the compiler's object writer stays ability-level independent of the layout and
binding code. The process gate is a `strace`-class trace (macOS: `fs_usage` or a spawn
wrapper) over the link step, counting execs of the platform linker, not a source grep.

## shared ops (c14)

Two tables exist today. omega's op graph is `proxima-tensor/src/op.rs` (a backward-only DAG:
`op.rs:9-17` states that references point backwards and a linear scan is the topological
order), consumed by `omega/src/msl/`, `omega/src/wgsl.rs`, `omega/src/cuda_ptx_store/` and
`omega/src/door/sink_mil.rs`. nova's ops are `Inst` variants in `proxima-nova/src/ir/inst.rs`,
lowered in `proxima-nova/src/aarch64/lower.rs` and encoded in `aarch64/encode.rs`. The same
scalar semantics are written twice, and a new op is added twice.

The shared boundary is a typed op table, not a shared graph: op id, arity, operand element
type and width, semantics (the CPU reference), and per-consumer lowering hooks. omega's
emitters and nova's lowering resolve an op id against the same table; omega's graph stays
backward-only because that invariant is what `shape::infer` and `bind::bind` rely on
(card PROXIMANOVA-43's assessment, option (b)).

| slice | content | falsifiable check |
|---|---|---|
| O1 | inventory: every op omega emits, every op nova lowers, and the exact overlap, with `file:line` | a table with no empty cell for a claimed shared op |
| O2 | one op (integer `Add` at `i32` and `i64`) defined once and consumed by both; nova's `Inst::Iadd` and omega's `Add` both resolve to that definition | `ops_shared=1 of=1`, `results=4 of=4` |
| O3 | integer `Sub`/`Mul`/`Div`/`Rem`, comparisons, casts; same CPU result through both | `ops_shared=N of=N`, `results=4N of=4N` |
| O4 | float ops through `proxima-numeric`'s `FloatLayout` (the shared float description card 43 already names) | identical bit patterns through both |
| O5 | omega's MSL/WGSL/PTX emitters read the table for their per-op code | each emitter's op coverage counted against the table |

Kill criterion (O1/O2): if omega's emitters require per-op code that cannot be keyed by the
table (a shape-dependent special case per op), stop at the shared table for the reference
evaluator and nova's lowering, and record the emitter gap as a measured fact rather than
widening the table.

## architecture

```
proxima-nova/                 workspace member, stable, edition 2024, rust-version 1.96
  src/ir/                     Function, Block, Value, Inst, Terminator, Type
  src/aarch64/                lower: Function -> MachFunction; encode: MachInst -> u32
  src/object.rs               Mach-O arm64 via `object` 0.40 (already Cargo.lock:3330)
  src/pipeline.rs             compile = lower -> encode per function, then object; run on prime
  src/bin/cargo-nova.rs       cargo subcommand: manifest -> units -> CommandPipe(rustc -Zcodegen-backend) -> run
proxima-nova-rustc/           NOT a workspace member: own [workspace], own rust-toolchain.toml (nightly, rustc-dev)
  src/lib.rs                  CodegenBackend -> rustc_public::rustc_internal::run(tcx, ..)
                              -> MIR bodies -> nova IR -> proxima-nova pipeline -> CompiledModule
```

Pipe shapes, using the `Pipe` contract `call(&self, In) -> impl Future<Output = Result<Out, Err>>`:

| stage | In | Out |
|---|---|---|
| source (adapter / test) | `()` | `Function` |
| lower | `Function` | `MachFunction` |
| encode | `MachFunction` | `Encoded` (symbol, code bytes, relocations) |
| object | `Vec<Encoded>` | `Vec<u8>` (Mach-O bytes) |

`Function`, `MachFunction`, `Encoded` are payload data, not pipes. A stage that a closure
over an existing combinator expresses gets no struct.

### decisions

| decision | chosen | why not the alternative |
|---|---|---|
| how MIR reaches nova | a `CodegenBackend` dylib calling `rustc_public` inside `codegen_crate` | a standalone `rustc_driver` would redo mono collection and linking, both of which the backend API hands over; cg_clif and cg_gcc are the precedent |
| nightly isolation | adapter excluded from the workspace, with its own toolchain file | the workspace pins stable `rust-version = "1.96"` (`Cargo.toml:78-79`); `rustc_private` would force nightly on every crate. `fuzz` is the precedent for an excluded crate (`Cargo.toml:74`) |
| object container | `object` 0.40 writer | already in `Cargo.lock:3330` and used by rustc itself; the compiler's work is the encoder, not the container |
| first target | aarch64-apple-darwin | host is arm64; x86_64 and ELF follow c1 |
| MIR locals | every local gets a stack slot; SSA promotion comes later as a pass | correct for every MIR shape from the first slice; speed comes after c2 |
| route through omega | not for c1 | omega's `Engine::Cpu` (`omega/src/backend.rs:114`) executes tensor plans, and a native object file that rustc links has no entry there. Revisit when nova lowers to a second backend |
| `Box<dyn Any>` in the adapter | kept, at that one boundary | `CodegenBackend::codegen_crate` returns it; rustc's trait fixes the type |
| where cargo-nova lives | a `[[bin]] name = "cargo-nova"` in proxima-nova | one crate, one epic; a separate crate would carry no API of its own |
| how cargo-nova runs rustc | `proxima_process::CommandPipe` (`proxima-process/src/lib.rs:57`) | spawning through `std::process` by hand would be a second process path beside the one proxima already has |
| unit graph source | its own manifest read first; `Cargo.lock` plus the already-fetched `~/.cargo/registry/src` for c6 | calling `cargo metadata` would make cargo-nova a cargo wrapper, not an alternative; `cargo fetch` stays the network edge until a fetch pipe replaces it |
